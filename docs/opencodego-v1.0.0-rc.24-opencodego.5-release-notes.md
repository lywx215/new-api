# v1.0.0-rc.24-opencodego.5 发布说明

## 修复内容

- 修复 OpenCodeGo（type 99）真实 HTTP 429 被统一按临时 RPM 限流处理，导致套餐、周额度或余额类错误即使命中失败关键词也不会自动禁用渠道的问题。
- OpenCodeGo 429 现在分为两类：
  - 命中管理员配置的失败关键词：自动禁用实际的 type 99 账号渠道。
  - 未命中关键词：视为普通 RPM 429，不永久禁用渠道；RPM保护开启且Redis可用时执行临时冷却，Redis故障时按既有策略fail-open。
- 本地软限流错误 `opencodego_rpm_soft_limit` 永不触发自动禁用。
- 上层 New API（type 60）收到下层账号 429 时保持启用，避免整个下层入口被切断。
- 渠道配置存在 `status_code_mapping` 时，内部策略使用映射前的原始上游状态识别429；客户端响应和普通状态码规则继续使用映射后状态，避免429映射为401/500后绕过OpenCodeGo保护。
- 自动禁用判断统一用于真实转发和批量/定时渠道测试；单次手动渠道测试仍只展示结果，不修改渠道状态。
- 自动禁用日志、渠道 `status_reason` 和通知中的错误原因统一脱敏，不记录OpenCode工作区ID、URL查询参数等敏感内容；单次手动渠道测试响应仍保留上游原始错误，便于管理员诊断。
- 管理端补充 OpenCodeGo 429 和自动禁用规则说明，并完成 en、zh、zh-TW、fr、ja、ru、vi 七种语言翻译。

## 渠道测试兼容性变化

批量、定时和单次渠道测试不再把所有非 200 响应统一包装成 HTTP 500 / `bad_response`，而是保留上游真实的 HTTP 状态码、错误码、错误正文和合法的 `Retry-After`。

因此，升级后的自动禁用状态码规则按真实状态生效。例如，上游真实返回 401 时会匹配 401，而不会再被当作 500。若现有配置曾依赖测试链路的人造 500，请在升级前检查 `AutomaticDisableStatusCodes` 和失败关键词配置。

## 升级要求

本版本不新增数据库迁移、Redis 键或配置字段，从 `v1.0.0-rc.24-opencodego.4` 升级后无需清理亲和或 RPM 数据。

实际管理 OpenCodeGo 账号渠道的下层节点必须满足：

```text
AutomaticDisableChannelEnabled=true
AutomaticDisableKeywords包含需要永久禁用的套餐/额度错误特征
每个type 99渠道auto_ban=true
```

推荐关键词示例：

```text
enable usage from your available balance
```

上下层使用独立数据库时，上述全局设置不会自动同步，必须在下层单独配置。上层可以继续开启自动禁用；代码会保护 type 60 不受下层账号 429 影响。

## 验证结果

- 根模块完整 Go 测试通过。
- relaykit 独立测试和构建通过。
- 前端 i18n 同步、定向 lint、TypeScript 检查和生产构建通过。
- 确定性测试覆盖 type 99 关键词 429、普通 429、type 60 保护、软限流保护、渠道级 `auto_ban`、批量/定时测试禁用和单次手动测试不禁用。
- 当前双实例测试环境使用包含核心关键词修复的本版本构建。使用一个真实业务请求验证：下层 type 99 收到周额度 429 后记录 `auto-disable reason: keyword` 并进入自动禁用；验证后已人工重新启用该渠道并精确清理其 RPM/cooldown 测试键。
- 原始状态码保留和日志脱敏的最终增量已通过确定性测试；本机Smart App Control阻止启动新生成的未签名Windows二进制，安全脚本已自动回滚到前一份健康的 `.5` 测试构建。因此该增量未在当前双实例做第二次运行时验收，正式部署应使用CI生成并受目标环境信任的发布产物。
